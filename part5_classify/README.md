## Run on the shared GPU instance

Activate `~/venv`, and use the FP16 ResNet-18 engine generated by Part 2 on this
same GPU and TensorRT version. The commands below are run from `~/lab8`.
The paths under `data/` are examples: substitute the actual Part 3/4 artifacts.

```bash
source ~/venv/bin/activate
bash part5_classify/run_part5.sh \
  --original data/original.npy \
  --received ordered=data/frames_rx.bin \
  --received shuffled=data/frames_rx_shuffled.bin
```

The script checks all 16 frames by default, runs the original and both received
datasets through the FP16 engine, and measures pinned H2D copies at batches
1, 8, and 16 with 50 warm-ups and 200 timed repetitions. A new timestamped
directory is created for each run. Use `--out results/part5/your-new-run` to
choose a new/empty directory explicitly.

If the engine is missing, coordinate with the owner of Part 2. Their existing
`bash part2_tensorrt/run_part2.sh` generates it in `models/` and also reruns the
Part 2 benchmarks. Do not rebuild it unnecessarily on the shared server.

## Input contract with Parts 3 and 4

Every image must already be **224 x 224 x 3 RGB bytes in HWC order**. Lossless
PNG or the exact transmitted raw bytes should be used for the original images.
Re-encoding the originals as JPEG can change pixels before comparison.

Supported formats:

| Input | Format and frame IDs |
|---|---|
| `.bin` | Headerless concatenation of raw images; 150,528 bytes per image. Default IDs 0..N-1 in file order. |
| `.npy` | `uint8` array shaped `(N, 224, 224, 3)`. Default IDs 0..N-1 in array order. |
| `.npz` | `frames`: the same uint8 NHWC array; `frame_ids`: an integer ID array with N entries. |
| Directory | One numbered PNG/BMP/JPEG or raw `.bin` per frame, e.g. `frame_0007.png`. The final integer in each filename is the frame ID. |

For headerless `.bin` / `.npy` that use a different frame order or ID numbering,
pass a JSON list containing the ID of each stored frame. Example: `[2, 0, 1, ...]`.

```bash
bash part5_classify/run_part5.sh \
  --original data/original.npy \
  --received shuffled=data/frames_rx_shuffled.bin \
  --received-ids shuffled=data/frames_rx_shuffled.ids.json
```

`--original-ids` supplies the equivalent list for the original input. `.npz` and
numbered directories already contain IDs and cannot use an ID sidecar.
All datasets are sorted by their explicit IDs before comparison. IDs must be
unique and the original/received ID sets must match.

If the receiver writes a header or records such as `(frame_id, length, bytes)`,
that format needs an explicit adapter. This reader deliberately rejects partial
frames and does not guess header offsets. A 16-frame headerless file is exactly
**2,408,448 bytes**. If a receiver writes frames in completion order, preserve
the IDs; a shuffled PCAP does not guarantee shuffled-file frame order.

## What the program measures

1. Load and align the original and reconstructed images on the CPU; verify exact
   byte equality separately from class equality.
2. Stage raw uint8 image bytes in pinned CPU memory, then copy them to the GPU.
3. On the GPU, convert NHWC to NCHW float32 and divide by 255. Apply
   `ResNet18_Weights.DEFAULT.transforms()` to that float GPU tensor: bilinear
   resize to 256, center crop to 224, and normalization using the preset's
   ImageNet mean and standard deviation. Cast to the engine's FP16 input type.
4. Call the existing `TRTRunner` with the GPU buffer on the same nondefault CUDA
   stream. Synchronize before reading the logits on the CPU.
5. Compare every received image's top-1 class with its original image. Record
   per-frame class IDs/names, byte differences, and maximum absolute logit error.
6. Time **only** pinned CPU-to-GPU uint8 copies using CUDA events, already-pinned
   input memory, and a preallocated destination. File reads, CPU pinning,
   allocations, GPU preprocessing and inference are excluded. Report mean,
   median, P95, microseconds per image, and decimal GB/s. Raw samples are saved.

An untimed reference check compares the GPU preprocessing result against the
same torchvision preset executed on the CPU. This reference is a check, not the
actual classification path. Tiny floating-point interpolation differences are
allowed before/after FP16 rounding. The GPU path never normalizes images on CPU.

Classification agreement is a consistency check, **not accuracy against labeled
ImageNet ground truth**. The program exits nonzero on pixel or class mismatch.
It also rejects incorrect shapes/types, missing/duplicate IDs, missing engines,
non-FP16 input engines, invalid output logits, and failed copy verification.

## Saved evidence

- `input_validation.json`: frame IDs and per-frame byte differences.
- `results.json`: environment, source hashes, engine hash, run command, consistency
  counts and every measured copy-time sample.
- `predictions.csv`: per-image original/received classes and comparison results.
- `copy_timing.csv`: transfer timing table.
- `report.md`: English report section generated only after an actual GPU run.

The report explains that GPUNetIO can eliminate this CPU-to-GPU image copy by
receiving into GPU memory. It does not eliminate reassembly, preprocessing or
inference. Isolating this copy does not itself measure an end-to-end GPUNetIO
speedup. A full Part 5 submission still needs real Part 3/4 inputs and GPU results.

```bash
python -m unittest discover -s part5_classify/tests -v

  --original data/original.npy \

```

`--validate-only` checks image data and saves only `input_validation.json`;
it never creates a GPU result table or claims Part 5 passed.

## Optional synthetic smoke test

If Part 3/4 data is not ready, exercise this code with **explicitly synthetic**
fixtures. These do not replace DPDK outputs and must not be presented as real
Part 3/4 evidence in the lab report.

```bash
python part5_classify/make_test_inputs.py --out work/part5-smoke-inputs
bash part5_classify/run_part5.sh \
  --original work/part5-smoke-inputs/original.npy \
  --received synthetic_ordered=work/part5-smoke-inputs/ordered.bin \
  --received synthetic_shuffled=work/part5-smoke-inputs/shuffled.npz \
  --out results/part5/synthetic-smoke
```

Add `--validate-only` to the last command to exercise data matching without CUDA.
The smoke test uses the same 16 generated images in a different storage order,
with explicit IDs, to check ordering. No PCAP or DPDK receiver is involved.
The generator writes `FIXTURE_ONLY.json`; the classifier detects this marker
and labels a successful run `PASS_SYNTHETIC_ONLY`, including a warning in its
report. Keep the marker beside these fixtures so they retain their provenance.
